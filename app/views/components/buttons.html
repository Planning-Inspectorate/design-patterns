In progress

Buttons help users trigger actions and complete their journeys.

The button component allows users to carry out actions like:

  • launching a process: signing in or starting a service
  • continuing a process: saving progress or adding information
  • completing a process: submitting a form
  • ending a process: cancelling or deleting or signing out

We use 4 different styles of buttons:

  • default: for core actions
  • secondary: for supporting actions
  • warning: for destructive actions
  • start: to begin a service journey

Default, secondary and warning buttons can be used as part of a button group along with a link.

The GOV.UK design system contains buttons guidance for all these components.

Content

Button text should:

  • be no longer than 5 words
  • contain 1 or 2 action words (matching the immediate result of the button, not anticipating what will happen on the next screen)
  • be sentence case
  • use ‘and’ not ‘&’
  • directly relate to the heading or section
  • use consistent terminology

The use and placing of buttons will vary depending on the context you are designing for: whether that’s an external user flow, an internal staff admin interface or a static webpage accessible via Google.

Within an external user flow, buttons should be left aligned and placed at the bottom of a form with no essential content underneath that may be missed by a screenreader user.

Secondary buttons should be used for supporting actions that will not directly progress the user towards their user journey.

These might be:

  • Starting a sub-journey before returning to the primary user journey - like adding a document
  • Adding information to the current page - like using an address lookup tool or adding an additional item
  • Refining a view - like applying filters

Examples of secondary button text:

  • Add document
  • Add another
  • Upload new version
  • Save as draft
  • Open

Warning buttons are for destructive actions that are irreversible and would result in the loss of data or significant progress.

They should be used sparingly as the strong red colour can cause users stress, and should be used only on the final confirm an action screen of a destructive action.

Examples of warning button text:

  • Remove user
  • Delete document

Start buttons should be exclusively used to initiate the start of a new journey.

As they are technically <a> link HTML elements they should only be used to navigate the user, and will not directly complete any actions or submit any form data.

Examples of start button text:

  • Start now
  • Get started

Button groups should be used to horizontally group multiple actions together that directly relate to one another. They must be ordered in terms of priority, with default actions being on the left.

Optionally, you may also include a single link as part of the group which should be at the lowest priority on the right.

Examples of button group text:

  • Save and continue | Save as draft
  • Continue | Cancel

When not to use this component

Do not use button HTML elements for navigation instead of link HTML elements.

Assistive technologies announce links and buttons differently according to how they are defined.

  • <button> elements communicate, ‘this will do something immediately‘
  • <a> link elements communicate, ‘this will take me somewhere else‘

Find out more at WCAG 2.1 Understanding Name, Role, Value.

Despite this there are situations when validated by user research, where visually styling a link to look like a button (or button to look like a link) would benefit the user journey.

A good example of this would be the Start Button example which uses a <a> link HTML element while being styled as a button.

Accessibility

There are accessibility issues with button disabled states, as described on the GOV.UK buttons guidance. You should ensure any usage of disabled states is validated with user research.

4.5:1 colour contrast is required between text and background when using any non-standard colours.
